Practical 1: Creating MVC Project using ASP.NET Core

Aim:

To create a Model-View-Controller (MVC) web application using ASP.NET Core and understand its architecture.

Theory:

ASP.NET Core MVC is a framework for building web applications using the Model-View-Controller architectural pattern. This pattern separates an application into three main components: the Model (data and business logic), the View (UI logic), and the Controller (handling user input). This separation helps manage complexity and makes the application easier to test and maintain.

Working Steps:

  1. Create Project via CLI: Open Command Prompt. Navigate to your desired folder. Create a directory and the MVC project: 
    md practMVC
cd practMVC
dotnet new mvc --auth None
dotnet build
dotnet run
    Why? Using the CLI ensures all necessary packages and default files (Controllers, Views, wwwroot) are scaffolded correctly. Copy the listening URL (e.g., http://localhost:5083) and paste it into Chrome to verify it runs.
  2. Open in Visual Studio: Go to the practMVC folder, right-click the .csproj file -> Open with -> Visual Studio 2022. Press the green Play button.
  3. Add a Model: Right-click Models folder -> Add -> Class -> Name it StockQuote.cs. 
    namespace practMVC.Models
{
    public class StockQuote
    {
        public string? Symbol { get; set; }
        public int Price { get; set; }
    }
}
  4. Update Controller: Open Controllers/HomeController.cs. Modify the Index() method. Why? The controller is responsible for passing data to the view. 
    public IActionResult Index()
{
    var model = new StockQuote { Symbol = "Nike", Price = 3200 };
    return View(model);
}
  5. Update View: Open Views/Home/Index.cshtml. Replace content with. Why? The View uses the `@model` directive to strongly type the data it receives and renders it using Razor syntax. 
    @model practMVC.Models.StockQuote

@{
    ViewData["Title"] = "Home Page";
}

<div class="text-center">
    <h1 class="display-4">Welcome</h1>
    <h2>Stock Information</h2>
    <p>Symbol: @Model.Symbol</p>
    <p>Price: @Model.Price</p>
</div>
  6. Run the Project: Press the green Play button in Visual Studio or run dotnet run in the terminal. Open the localhost URL in your browser.

Common Problems & Solutions

Problem 1: "The localhost page isn't working" or Port Conflict.

  • Solution: Another application is using the same port. Open Properties/launchSettings.json in your project and change the port number (e.g., from 5083 to 5084).

Problem 2: "dotnet run" command not recognized.

  • Solution: Ensure the .NET SDK is installed and added to your system PATH. Restart your command prompt.

Output:

The browser displays the MVC web page with "Symbol: Nike" and "Price: 3200", demonstrating data flow from Controller to View.

Practical 2: Develop a Microservice using ASP.NET Core with a RESTful API

Aim:

To develop a microservice using ASP.NET Core Web API with a RESTful API to expose and manage application data using Entity Framework Core and SQL Server.

Theory:

Microservices architecture structures an application as a collection of loosely coupled, independently deployable services. A RESTful API uses standard HTTP methods (GET, POST, PUT, DELETE) to manage data. In this practical, we create an independent "USER" microservice with its own internal database.

Working Steps:

  1. Create Project: Create a new ASP.NET Core Web API project named USER. Set Framework to .NET 6.0, Auth to None. Delete default WeatherForecast.cs and WeatherForecastController.cs to keep the project clean.
  2. Add API Controller: Right-click Controllers -> Add -> Controller -> API Controller with read/write actions. Name it UserController.cs. This scaffolds basic CRUD endpoints.
  3. Create Entities: Create folders Database/Entities. Add a class User.cs: 
    namespace USER.Database.Entities
{
    public class User
    {
        public int UserId { get; set; }
        public string? Name { get; set; }
        public string? Address { get; set; }
        public int Contact { get; set; }
    }
}
  4. Install NuGet Packages: Right-click Dependencies -> Manage NuGet Packages. Install:
    • Microsoft.EntityFrameworkCore
    • Microsoft.EntityFrameworkCore.Tools (Needed for migrations)
    • Microsoft.EntityFrameworkCore.SqlServer (Provider for SQL Server)
  5. Create Database Context: Add class DatabaseContext.cs in the Database folder. This acts as a bridge between your code and the database. 
    using Microsoft.EntityFrameworkCore;
using USER.Database.Entities;

namespace USER.Database
{
    public class DatabaseContext : DbContext
    {
        public DbSet<User> Users { get; set; }

        protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
        {
            optionsBuilder.UseSqlServer(@"Data Source=(localdb)\MSSQLLocalDB;Initial Catalog=Database;Integrated Security=True;Connect Timeout=30;Encrypt=False;Trust Server Certificate=False;Application Intent=ReadWrite;Multi Subnet Failover=False");
        }
    }
}
  6. Create Table: Go to View -> SQL Server Object Explorer. Right-click Databases -> Add New Database (Name: Database). Expand it, right-click Tables -> Add New Table. Add columns: UserId (PK, int), Name (nvarchar), Address (nvarchar), Contact (int). Update Database.
  7. Run Migrations: Go to Tools -> NuGet Package Manager -> Package Manager Console. This creates the database schema based on your C# classes. 
    add-migration initial
update-database -verbose
  8. Implement RESTful API Methods: Open UserController.cs and replace with full CRUD logic: 
    using Microsoft.AspNetCore.Mvc;
using USER.Database;
using USER.Database.Entities;

namespace USER.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class UserController : ControllerBase
    {
        private readonly DatabaseContext _context = new DatabaseContext();

        // GET: api/User
        [HttpGet]
        public IActionResult Get() { return Ok(_context.Users.ToList()); }

        // GET: api/User/5
        [HttpGet("{id}")]
        public IActionResult Get(int id)
        {
            var user = _context.Users.Find(id);
            if (user == null) return NotFound();
            return Ok(user);
        }

        // POST: api/User
        [HttpPost]
        public IActionResult Post([FromBody] User model)
        {
            try
            {
                _context.Users.Add(model);
                _context.SaveChanges();
                return StatusCode(StatusCodes.Status201Created, model);
            }
            catch (Exception ex)
            {
                return StatusCode(StatusCodes.Status500InternalServerError, ex.Message);
            }
        }

        // PUT: api/User/5
        [HttpPut("{id}")]
        public IActionResult Put(int id, [FromBody] User model)
        {
            var entity = _context.Users.FirstOrDefault(e => e.UserId == id);
            if (entity == null) return BadRequest("User not found.");
            
            entity.Name = model.Name;
            entity.Address = model.Address;
            entity.Contact = model.Contact;
            _context.SaveChanges();
            return Ok();
        }

        // DELETE: api/User/5
        [HttpDelete("{id}")]
        public IActionResult Delete(int id)
        {
            var entity = _context.Users.FirstOrDefault(e => e.UserId == id);
            if (entity == null) return NotFound();
            
            _context.Users.Remove(entity);
            _context.SaveChanges();
            return NoContent();
        }
    }
}
  9. Run and Test: Press F5 to run. The browser opens Swagger UI. Test the GET, POST, PUT, DELETE endpoints. You can also use Postman with the URL https://localhost:7286/api/User.

Common Problems & Solutions

Problem 1: "No DbContext was found in assembly" error during migration.

  • Solution: Ensure your DatabaseContext.cs file is in the correct namespace and inherits from DbContext. Also, make sure you have the Microsoft.EntityFrameworkCore.Tools package installed.

Problem 2: "Cannot connect to SQL Server" or "Login failed" error.

  • Solution: Check your connection string in DatabaseContext.cs. Ensure the Data Source matches your local SQL Server instance (e.g., (localdb)\MSSQLLocalDB or .\SQLEXPRESS).

Problem 3: Database already exists error.

  • Solution: In SQL Server Object Explorer, delete the existing Database manually, then run update-database again.

Output:

The application runs as an independent microservice. Swagger and Postman successfully perform CRUD operations on the User data, returning JSON responses.

Practical 3: Working with CircleCI for continuous integration

Aim:

To implement Continuous Integration (CI) using CircleCI for a Python application.

Theory:

Continuous integration is a software development strategy that increases the speed of development while ensuring the quality of the code. Developers continually commit changes in small increments, and each change is automatically built and tested by the CI server before it is merged into the product.

Working Steps:

  1. Prerequisites: Download and install GitHub Desktop, Git for Windows (Git Bash), and VS Code. Install the Python extension in VS Code.
  2. Create Project Folder: Create a folder named CIRCLECI. Open it in VS Code.
  3. Create Python Files: Inside the folder, create main.py: 
    def to_upper(name):
    return name.upper()

def say_hello(name):
    print(f'Hello, {name}')

if __name__ == '__main__':
    name='TrainwithTannu'
    say_hello(name)
    up = to_upper(name)
    print(up)
    Create test.py: 
    import unittest
from main import to_upper

class MyTestCase(unittest.TestCase):
    def test_to_upper(self):
        name="Tannu"
        upper_name=to_upper(name)
        self.assertEqual(upper_name, "TANNU")

if __name__ == '__main__':
    unittest.main()
  4. Create README: Create readme.md and add basic instructions (e.g., "How to run the code").
  5. Push to GitHub: Open GitHub Desktop. Sign in. Create a new repository on GitHub named CircleCI-Python3. Clone it locally. Copy your files into the cloned repo. Open Git Bash, navigate to the repo, and run: 
    git add .
git commit -m "added python file by tannu"
git push origin main
  6. Setup CircleCI: Go to circleci.com and log in with GitHub. Set up the project by selecting your repository.
  7. Create CircleCI Config: In your project root, create a folder .circleci and inside it create config.yml. Why? This file tells CircleCI exactly how to build and test your code. 
    version: 2.1

jobs:
  build:
    docker:
      - image: cimg/python:3.11
    steps:
      - checkout
      - run: python main.py
  test:
    docker:
      - image: cimg/python:3.11
    steps:
      - checkout
      - run: python test.py

workflows:
  build_and_test_deploy:
    jobs:
      - build
      - test:
          requires:
            - build
  8. Push and Verify: Commit and push the .circleci/config.yml file using Git commands. Go to the CircleCI dashboard. You will see the "build" and "test" jobs running. Click on them to see the successful execution of your Python files.

Common Problems & Solutions

Problem 1: "Config file not found" or "Syntax Error" in CircleCI.

  • Solution: Ensure the folder is named exactly .circleci (with the dot) and the file is config.yml. YAML is very strict about indentation; ensure you use spaces (not tabs) and the structure matches exactly.

Problem 2: "Permission denied" when running python scripts.

  • Solution: Ensure the files are committed and pushed to GitHub correctly. Check if the repo is public or if CircleCI has been granted access to private repos.

Output:

CircleCI dashboard shows a successful pipeline with both "build" and "test" jobs passing. The logs confirm that main.py and test.py executed correctly.

Practical 4: Deploy an application using Ocelot API

Aim:

To deploy an ASP.NET Core MVC application behind an Ocelot API Gateway and demonstrate request routing.

Theory:

Ocelot is an open-source, lightweight, and scalable .NET Core-based API Gateway. It provides a single, unified entry point for clients to access multiple downstream services. In this practical, an ASP.NET Core MVC application acts as the downstream microservice, and the Ocelot project acts as the gateway forwarding client requests to the MVC application.

Working Steps:

  1. Create MVC App: Create an ASP.NET Core Web App (MVC) named pracMVC. Add a model StockQuote.cs: 
    namespace pracMVC.Models
{
    public class StockQuote
    {
        public string? Symbol { get; set; }
        public int Price { get; set; }
    }
}
  2. Update Controller: In HomeController.cs: 
    public IActionResult Index()
{
    var model = new StockQuote { Symbol = "Nike", Price = 3200 };
    return View(model);
}
  3. Update View: In Views/Home/Index.cshtml: 
    @model pracMVC.Models.StockQuote
@{
    ViewData["Title"] = "Home Page";
}
<div class="text-center">
    <h1 class="display-4">Welcome to MVC App</h1>
    <h2>Stock Quote</h2>
    <p>Symbol: @Model.Symbol</p>
    <p>Price: @Model.Price</p>
</div>
  4. CRUCIAL FIX: Open pracMVC/Program.cs. Comment out app.UseHttpsRedirection();. Why? Ocelot communicates via HTTP internally. If the MVC app forces HTTPS redirection, the gateway will get a 307 redirect and fail to fetch the page. 
    // app.UseHttpsRedirection();
  5. Set MVC Port: Open pracMVC/Properties/launchSettings.json. Ensure the HTTP profile uses port 5083. 
    "applicationUrl": "http://localhost:5083"
  6. Create Ocelot Project: Right-click Solution -> Add -> New Project -> ASP.NET Core Empty. Name it ocelotAPI. Install the Ocelot NuGet package.
  7. Configure Ocelot JSON: Add a new item ocelot.json to the ocelotAPI project. This file defines the routing rules. 
    {
  "Routes": [
    {
      "DownstreamPathTemplate": "/Home/Index",
      "DownstreamScheme": "http",
      "DownstreamHostAndPorts": [
        {
          "Host": "localhost",
          "Port": 5083
        }
      ],
      "UpstreamPathTemplate": "/gateway/home",
      "UpstreamHttpMethod": [ "GET" ]
    }
  ],
  "GlobalConfiguration": {
    "BaseUrl": "http://localhost:5252"
  }
}
    Important: Right-click ocelot.json -> Properties -> Set "Copy to Output Directory" to "Copy if newer". Visual Studio does not do this by default, and Ocelot will crash if it can't find this file at runtime.
  8. Configure Ocelot Program.cs: 
    using Ocelot.DependencyInjection;
using Ocelot.Middleware;

var builder = WebApplication.CreateBuilder(args);

// Load the ocelot.json file
builder.Configuration.AddJsonFile("ocelot.json", optional: false, reloadOnChange: true);

// Add Ocelot services
builder.Services.AddOcelot();

var app = builder.Build();

// Use Ocelot middleware
await app.UseOcelot();

app.Run();
  9. Set Gateway Port: Open ocelotAPI/Properties/launchSettings.json. Ensure the HTTP profile uses port 5252 and sets the launch URL to the gateway path. 
    "applicationUrl": "http://localhost:5252",
"launchUrl": "gateway/home"
  10. Multiple Startup Projects: Right-click Solution -> Configure Startup Projects -> Select Multiple startup projects -> Set both pracMVC and ocelotAPI to Start.
  11. Run: Press F5. Both terminals will open. Wait for them to say "Now listening on...". Navigate to http://localhost:5252/gateway/home.

Common Problems & Solutions (Practical 4 Focus)

Problem 1: "502 Bad Gateway" or "Connection Refused".

  • Solution: Ocelot cannot reach your MVC app.
    1. Check if pracMVC is actually running. Look at its terminal window.
    2. Check the port number in ocelot.json ("Port": 5083). It MUST match the port in pracMVC/Properties/launchSettings.json.

Problem 2: Ocelot starts but crashes immediately with "ocelot.json not found".

  • Solution: You forgot to set the file properties. Right-click ocelot.json in Solution Explorer -> Properties -> Set Copy to Output Directory to Copy if newer or Copy always.

Problem 3: "307 Temporary Redirect" or "HTTPS error".

  • Solution: Open pracMVC/Program.cs and ensure app.UseHttpsRedirection(); is commented out. Ocelot works over HTTP internally.

Problem 4: Visual Studio only opens one project (either MVC or Ocelot) instead of both.

  • Solution: You need to set up Multiple Startup Projects. Right-click the Solution (the very top item in Solution Explorer) -> Configure Startup Projects... -> Select Multiple startup projects -> Change the Action for both pracMVC and ocelotAPI to Start.

Problem 5: 404 Not Found on Gateway URL.

  • Solution: Check your exact URL. The browser must match the UpstreamPathTemplate in ocelot.json exactly. If the file says /gateway/home, you must type http://localhost:5252/gateway/home.

Output:

The browser at http://localhost:5252/gateway/home displays the MVC page ("Symbol: Nike", "Price: 3200") showing that Ocelot successfully routed the request to the downstream MVC app on port 5083.

Practical 5: Usage of Docker

Aim:

To build and run a Docker image as a container and share the image using Docker Hub.

Theory:

Docker packages software into standardized units called containers that have everything the software needs to run including libraries, system tools, code, and runtime. Docker Hub is a registry service provided by Docker for finding and sharing container images.

Working Steps:

  1. Create Project: Create a new ASP.NET Core Web API project named DockerPractical. Select .NET 6.0 and check Enable Docker.
  2. Install Docker Desktop: If prompted, install Docker Desktop for Windows. Enable Windows Hypervisor Platform and Windows Subsystem for Linux in Windows Features. Run wsl --update in an admin terminal if needed.
  3. Run and Verify: Select the Docker profile in Visual Studio and click Play. Open Docker Desktop -> Containers. You will see DockerPractical running.
  4. Verify Image: Open Command Prompt. Run: 
    docker images
  5. Login to Docker Hub: 
    docker login
    (Enter your Docker Hub username and password).
  6. Tag the Image: Replace yourusername with your actual Docker Hub username: 
    docker tag dockerpractical:dev yourusername/dockerpractical
  7. Push to Docker Hub: 
    docker push yourusername/dockerpractical
  8. Verify on Docker Hub: Go to hub.docker.com -> Repositories. You will see your dockerpractical repository with the image.
  9. Pull Image (Simulating Sharing): Delete the local image to prove you can download it again: 
    docker rmi yourusername/dockerpractical:latest
docker pull yourusername/dockerpractical:latest

Common Problems & Solutions

Problem 1: "Docker command failed with exit code 1" / "pipe/dockerDesktopLinuxEngine" not found.

  • Solution: Docker Desktop is not running. Open Docker Desktop from your start menu and wait for the whale icon to stop animating.

Problem 2: "The current user is not in the 'docker-users' group".

  • Solution: Open Command Prompt as Administrator and run: net localgroup docker-users "your-username" /add. Then sign out and sign back in to Windows.

Problem 3: "Port is already allocated" when running the container.

  • Solution: Another process is using the port. Change the port mapping in the docker run command (e.g., -p 5001:5000) or stop the conflicting application.

Output:

The application successfully builds and runs in a Docker container. The image is tagged, pushed to Docker Hub, and can be pulled back down from the repository, demonstrating successful image sharing.
